# ModelRate 模型中转站倍率计算网站调研报告

## 一、报告摘要

ModelRate 适合定位为一个 **AI API 成本透明化工具站**，而不是单纯的“倍率计算器”。

中文 AI API 用户真正的痛点并不只是“不知道倍率怎么算”，而是：

- 不知道某个模型在官方、OpenRouter、中转站之间到底哪个更便宜。
- 不知道 `1x / 1.5x / 0.5x` 换算成人民币后实际是多少钱。
- 不知道 One-API / New API 的模型倍率、补全倍率、分组倍率应该怎么配置。
- 不知道 Claude、GPT、Gemini、DeepSeek、Grok 等模型分别适合什么场景。
- 不知道中转站是否靠谱、是否支持微信/支付宝/USDT、起充多少、有没有跑路风险。
- 不知道自己的使用量一个月大概会花多少钱。

所以，ModelRate 最有价值的方向是：

> 围绕“模型价格、倍率换算、中转站对比、模型选择、成本估算”建立一个工具 + 内容 + 导购型网站。

盈利模式上，可以采用：

- Google AdSense 广告。
- 中转站推荐链接 / 返佣。
- 中转站赞助位。
- 服务商投稿 / 认证。
- 后期提供价格 API、嵌入式计算器或专业版工具。

但核心前提是：网站必须先建立“可信、透明、实用”的工具属性。如果一开始就做成推荐站或广告站，会削弱用户信任，也不利于 SEO 和 AdSense 审核。

## 二、市场背景

### 1. 中文用户对 AI API 中转站的需求明显存在

国内用户直接使用 OpenAI、Anthropic、Google Gemini 等官方 API，通常会遇到：

- 海外信用卡门槛。
- 支付不方便。
- 网络访问问题。
- 官方账号风控问题。
- 多模型切换麻烦。
- API 账单单位难理解。

因此中文市场出现了大量 AI API 中转站。它们通常提供：

- 人民币充值。
- 微信 / 支付宝 / USDT 支付。
- OpenAI、Claude、Gemini、DeepSeek、Grok 等统一接口。
- One-API / New API 风格的模型倍率计费。
- 低起充、小额试用。
- 推荐返佣或注册送额度。

但这个市场同时也有明显问题：

- 价格不透明。
- 模型倍率和真实成本难理解。
- 服务商质量参差不齐。
- 新站跑路风险高。
- 同一模型在不同中转站的价格差距很大。
- 用户很难判断“便宜”和“稳定”之间的权衡。

这正是 ModelRate 可以切入的空间。

## 三、竞品调研

### 1. HowToken：中转站导航型

参考：[HowToken](https://howtok.net/)

HowToken 是一个 AI 中转站导航网站，页面显示其收录了大量中转站，并支持按模型、支付方式、起充金额等条件筛选。

它的核心价值是：

- 让用户快速知道有哪些中转站。
- 展示每家中转站支持哪些模型。
- 展示支付方式，例如微信、支付宝、USDT、VISA。
- 展示起充金额。
- 提供投稿入口。
- 用 FAQ 教育用户如何选择中转站。

值得借鉴的点：

- 中转站卡片结构清晰。
- 支持模型标签很直观。
- 起充金额是中文用户非常关心的筛选项。
- FAQ 内容直接解释了中转站风险、价格透明度、跑路风险等。
- 通过推荐链接做导流，有明确商业化空间。

不足之处：

- 更偏导航站，不是深度计算工具。
- 模型价格、倍率、最终成本的计算能力较弱。
- 缺少按模型横向比价。
- 缺少预算估算、Token 成本计算、One-API 配置辅助。
- 数据可信度主要依赖站点整理，缺少可验证的价格来源和更新时间机制。

对 ModelRate 的启发：

> ModelRate 可以做“更工具化、更价格透明、更偏计算”的 HowToken。

### 2. Help AIO：模型比价 + 可用率监控型

参考：[Help AIO AI模型比价](https://www.helpaio.com/transit/compare)

Help AIO 的中转站比价页更接近 ModelRate 的潜在方向。它有：

- 预算输入。
- Token 数估算。
- 图表 / 表格切换。
- Claude、GPT、Gemini 等厂商筛选。
- 按量 / 包月筛选。
- 可用率筛选。
- 支持渠道筛选。
- 站点排名、模型比价、Bench 测试、简约表格等视图。

它的核心价值是：

- 不只告诉用户有哪些中转站，还试图告诉用户“哪个更划算”。
- 通过预算反推 Token 数。
- 加入可用性数据，让价格之外也有稳定性维度。
- 更像一个“中转站决策工具”。

值得借鉴的点：

- `预算 -> 可用 Token 数` 是很好的工具入口。
- “图表 + 表格”适合同时服务普通用户和开发者。
- 可用率筛选可以提升信任度。
- 按模型横向比价非常适合 SEO 和导购转化。
- Bench / 实测数据是差异化壁垒。

不足之处：

- 对 One-API / New API 的倍率公式解释不够强。
- 对模型基础价格、官方价格、倍率价之间的关系可以更透明。
- 如果数据更新机制不清晰，用户仍然会怀疑价格准确性。
- 页面工具感较强，但内容矩阵和知识教育还可以扩展。

对 ModelRate 的启发：

> ModelRate 应该把“比价”和“倍率计算”结合起来，而不是只做其中一个。

### 3. One-API 模型定价倍率计算器：公式工具型

参考：[One-API 模型定价倍率计算器](https://onecalc.atlassc.net/)

这个网站非常聚焦，核心是解释和计算 One-API 的模型倍率。

它给出的关键概念是：

- One-API 以 `$0.002 / 1K tokens` 作为 1 倍。
- 换算成 `$2 / 1M tokens`。
- 模型倍率用于表达输入价格。
- 补全倍率用于表达输出价格相对输入价格的倍数。
- 分组倍率用于对不同用户组额外加权。
- 公式类似：`额度 = 分组倍率 * 模型倍率 * (提示 token + 补全 token * 补全倍率)`。

它的核心价值是：

- 帮站长或使用者把官方价格转成 One-API 后台可配置的倍率。
- 可以添加模型。
- 可以在 1K / 1M token 单位之间切换。
- 数据存在浏览器本地，适合轻工具使用。

值得借鉴的点：

- 倍率公式解释必须清楚。
- `输入价格 -> 模型倍率 -> 补全倍率` 是 ModelRate 的基础能力。
- 支持自定义模型很重要。
- 对站长用户来说，复制配置结果比单纯展示价格更有价值。

不足之处：

- 界面偏工具表格，普通用户不一定理解。
- 没有中转站对比。
- 没有模型选择建议。
- 没有 SEO 内容体系。
- 没有商业化入口。

对 ModelRate 的启发：

> ModelRate 的第一个核心工具应该比 One-API 计算器更完整：既服务站长，也服务普通 API 用户。

### 4. GO-MODEL：服务商官网型

参考：[GO-MODEL](https://www.go-model.com/)

GO-MODEL 是中转服务商自身的网站，强调：

- 一站式大模型 API 中转。
- 低成本接入全球模型。
- `1 RMB = 1 USD 算力` 这样的价格心智。
- 低延迟、高可用、自动重连。
- 按量计费、按次计费。
- 线路倍率。
- 公式：`(基础模型 · 计费方式) × 线路倍率 = 模型最终价格`。

它代表的是另一类竞品：不是工具站，而是直接销售服务。

值得借鉴的点：

- 线路倍率是中转站用户真实会遇到的概念。
- 模型最终价格不仅受模型基础价格影响，也受线路、渠道、分组影响。
- 服务商官网通常会用“便宜、稳定、全模型、支付方便”作为核心卖点。
- 这类服务商未来可能是 ModelRate 的广告主或推荐合作方。

不足之处：

- 它不是中立第三方。
- 用户需要横向比较多个服务商，而不是只看单个官网。
- 服务商自己的价格宣传需要被工具站转化成可比较的数据。

对 ModelRate 的启发：

> ModelRate 可以站在用户角度，把服务商官网上的价格、线路、倍率转成统一口径。

### 5. 海外 LLM 价格计算器与模型库

海外有不少 LLM API 成本计算和模型对比网站，例如：

- [OpenRouter Pricing](https://openrouter.ai/pricing)
- [OpenRouter Models API](https://openrouter.ai/docs/api/api-reference/models/get-models)
- [LLMCompare](https://llmcompare.dev/)
- [LiteLLM model_prices_and_context_window.json](https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json)
- [Portkey-AI/models](https://github.com/Portkey-AI/models)

这类产品通常关注：

- 不同模型的输入价格。
- 不同模型的输出价格。
- 上下文长度。
- 模态能力。
- Provider 差异。
- 每月调用成本。
- 模型比较。
- API 价格数据源。

值得借鉴的点：

- 模型价格数据应该结构化，不应该只写死在页面里。
- 价格单位要统一，例如全部转成 `USD per 1M tokens`。
- 模型需要有 provider、上下文、模态、能力标签。
- 用户需要按任务场景筛选模型。
- OpenRouter、LiteLLM、Portkey 这类公开数据源可以作为初始模型库参考。

中文市场的差异：

- 海外网站一般不理解“中转站倍率”。
- 不关注微信、支付宝、起充金额。
- 不关注 One-API / New API 配置。
- 不关注中转站跑路风险。
- 不关注人民币预算。
- 不关注中文开发者的 Claude Code、Codex、Cursor、Cline 等实际使用场景。

对 ModelRate 的启发：

> ModelRate 的差异化不是再做一个英文 LLM 价格计算器，而是把“国际模型价格数据”和“中文中转站倍率体系”打通。

## 四、目标用户分析

### 1. 普通 AI API 用户

这类用户的典型问题是：

- 我每个月用 Claude / GPT / Gemini 大概多少钱？
- 中转站显示 `1.2x`，到底贵不贵？
- 充值 50 元能用多久？
- 哪个中转站支持支付宝？
- 哪个站便宜但不要太容易跑路？

他们需要的是：

- 简单成本计算器。
- 预算反推。
- 中转站推荐。
- 风险提示。
- 模型选择建议。

### 2. 开发者和 AI 工具用户

这类用户常用：

- Claude Code
- Codex
- Cursor
- Cline
- Continue
- OpenCode
- Chatbox
- Cherry Studio
- 自建 Bot
- RAG 应用
- 工作流自动化

他们关心：

- 长上下文成本。
- 输出 token 成本。
- Agent 多轮调用成本。
- 缓存是否省钱。
- 不同模型在 coding、reasoning、translation、summarization 上的性价比。
- 中转站是否兼容 OpenAI API 格式。
- 是否支持 Claude / Gemini / DeepSeek / Grok。
- API 稳定性和速度。

他们需要的是：

- 更专业的模型筛选。
- 场景化成本估算。
- API 兼容性说明。
- 模型对比。
- 中转站稳定性信息。

### 3. One-API / New API 站长

这类用户更偏 B 端或技术运营。

他们关心：

- 官方价格如何转成模型倍率。
- 输出价格如何转成补全倍率。
- 分组倍率怎么设计。
- 线路倍率怎么表达。
- 如何避免亏损。
- 如何设计不同用户组价格。
- 如何给模型定价更合理。

他们需要的是：

- One-API 倍率计算器。
- New API 倍率计算器。
- 批量模型导入。
- 模型价格表。
- 推荐配置导出。
- 盈亏模拟。

### 4. 中转站服务商

这类用户未来是潜在广告主。

他们关心：

- 被收录。
- 获得曝光。
- 获得推荐链接转化。
- 展示模型支持范围。
- 展示支付方式和优惠。
- 建立可信度。

他们需要的是：

- 投稿入口。
- 服务商详情页。
- 赞助位。
- 认证标识。
- 点击统计。
- 优惠码展示。

但需要注意：服务商商业合作不能破坏 ModelRate 的中立性。推荐关系必须明确标注。

## 五、产品定位建议

建议 ModelRate 的一句话定位是：

> ModelRate 是面向中文 AI API 用户的模型价格、倍率计算和中转站对比工具。

更具体一点：

> 帮助用户把官方模型价格、中转站倍率、人民币预算和实际 Token 用量转换成可理解、可比较、可决策的成本结果。

不建议定位成：

- “AI 中转站大全”：因为 HowToken 已经很接近，而且纯导航壁垒较弱。
- “最便宜中转站排行榜”：容易变成广告站，也容易失去可信度。
- “AI API 推荐站”：太泛，SEO 和用户心智都不够聚焦。
- “模型评测站”：Bench 成本高，且初期不容易建立权威。

建议主定位是：

> 计算器 + 比价 + 选择指南。

## 六、推荐产品结构

### 1. 核心工具一：模型成本计算器

这是最重要的入口。

用户输入：

- 模型。
- 输入 token 数。
- 输出 token 数。
- 请求次数。
- 日使用量或月使用量。
- 汇率。
- 是否使用中转站倍率。
- 是否计算缓存。
- 是否计算 reasoning tokens。

输出：

- 单次成本。
- 每日成本。
- 每月成本。
- 每 1K token 成本。
- 每 1M token 成本。
- 人民币成本。
- 预算可用次数。
- 与其他模型的对比。

适合 SEO 页面：

- `Claude API Cost Calculator`
- `GPT API Cost Calculator`
- `Gemini API Cost Calculator`
- `AI Token Cost Calculator`
- `模型 API 价格计算器`

### 2. 核心工具二：One-API / New API 倍率计算器

用户输入：

- 官方输入价格。
- 官方输出价格。
- 价格单位：每 1K / 每 1M token。
- 基准价格。
- 汇率。
- 分组倍率。
- 线路倍率。
- 目标利润率。

输出：

- 模型倍率。
- 补全倍率。
- 最终扣费公式。
- 每 1M token 人民币成本。
- 建议后台配置。
- 复制配置按钮。

这个工具服务的是更专业的站长和开发者。它的流量可能没有普通成本计算器大，但转化价值更高，也更容易形成专业口碑。

### 3. 核心工具三：模型选择器

用户选择自己的场景：

- 写代码。
- Agent 编程。
- 长文总结。
- 翻译。
- RAG。
- 客服机器人。
- 低成本聊天。
- 图像理解。
- 高质量推理。
- 大上下文处理。

系统输出推荐模型：

- 最低成本选择。
- 平衡选择。
- 高质量选择。
- 长上下文选择。
- 中转站可用选择。

每个推荐结果应该解释：

- 为什么推荐。
- 输入成本如何。
- 输出成本如何。
- 上下文长度是否足够。
- 是否适合中文。
- 是否适合代码。
- 是否需要注意隐藏成本。

### 4. 核心工具四：中转站对比目录

字段建议：

- 站点名称。
- 官网域名。
- 支持模型。
- 支持 provider。
- 支付方式。
- 起充金额。
- 是否支持按量。
- 是否支持订阅。
- 是否有赠金。
- 是否有推荐码。
- 客服渠道。
- 数据更新时间。
- 风险标签。
- 推荐链接。

筛选项建议：

- 支持 Claude。
- 支持 OpenAI。
- 支持 Gemini。
- 支持 DeepSeek。
- 支持 Grok。
- 支持支付宝。
- 支持微信。
- 支持 USDT。
- 起充低于 10 元。
- 有新用户赠金。
- 有公开价格表。
- 有客服渠道。

排序建议：

- 起充最低。
- 支持模型最多。
- 价格透明度高。
- 最近更新。
- 推荐站点。
- 风险较低。

### 5. 核心工具五：预算反推工具

用户输入：

- 预算，例如 `¥10 / ¥50 / ¥100 / $10`。
- 使用场景。
- 模型。
- 输入输出比例。
- 中转站倍率。

输出：

- 可以调用多少次。
- 可以处理多少 token。
- 可以跑多少次 agent 任务。
- 不同模型下的预算差异。
- 推荐模型组合。

这个功能非常适合普通用户，因为他们往往不是从 token 开始思考，而是从“我充 50 元能用多久”开始思考。

## 七、内容策略

如果网站要依靠 AdSense 和搜索流量，不能只有工具页面。需要配套高质量内容。

### 1. 基础解释类内容

建议准备：

- 什么是 token？
- 什么是模型倍率？
- 什么是补全倍率？
- One-API 倍率怎么算？
- New API 模型价格怎么配置？
- 为什么输出 token 比输入 token 贵？
- 为什么 Claude Code / Codex 消耗这么快？
- 什么是 cached input？
- 什么是 reasoning token？
- 什么是 context window？
- 中转站为什么比官方便宜或贵？

这些文章的目标是承接长尾搜索。

### 2. 模型价格类内容

建议准备：

- Claude API 价格说明。
- GPT API 价格说明。
- Gemini API 价格说明。
- DeepSeek API 价格说明。
- Grok API 价格说明。
- OpenRouter 价格怎么看。
- Claude Sonnet vs GPT vs Gemini 成本对比。
- 适合写代码的模型价格对比。
- 适合长上下文的模型价格对比。

这类页面既适合 SEO，也适合内链到计算器。

### 3. 中转站选择类内容

建议准备：

- 如何选择 AI API 中转站？
- 中转站起充金额怎么看？
- 支付宝 / 微信 / USDT 中转站怎么选？
- 中转站有哪些风险？
- 如何小额测试一个中转站？
- 中转站价格透明度怎么看？
- 推荐码、赠金、邀请返佣要注意什么？
- 为什么不建议一次充值太多？

这类内容能支撑导购转化。

### 4. 场景化成本内容

建议准备：

- 用 Claude Code 一个月大概多少钱？
- 用 Codex 一个月大概多少钱？
- 用 Cursor 接 API 怎么估算成本？
- 一个客服机器人每月 API 成本怎么算？
- 一个 RAG 应用每月 API 成本怎么算？
- 翻译 100 万字需要多少 API 成本？
- 总结 1000 篇文章要花多少钱？

这类内容最容易吸引真实用户，因为问题具体。

## 八、数据准备

### 1. 模型数据

每个模型至少需要：

- 模型 ID。
- 展示名称。
- Provider。
- 输入价格。
- 输出价格。
- 缓存输入价格。
- 上下文长度。
- 最大输出长度。
- 是否支持图片。
- 是否支持音频。
- 是否支持 reasoning。
- 是否支持 function calling。
- 数据来源。
- 更新时间。

内部建议统一存储成：

```text
USD per 1M tokens
```

这样不管前端展示 `per 1K` 还是 `per 1M`，都可以统一换算。

### 2. 中转站数据

每个中转站至少需要：

- 名称。
- 域名。
- Logo。
- 支持模型。
- 支持 provider。
- 支付方式。
- 起充金额。
- 计费方式。
- 是否有公开价格表。
- 是否有赠金。
- 是否有推荐链接。
- 客服渠道。
- 数据来源。
- 更新时间。
- 风险标签。
- 备注。

风险标签建议包括：

- 新站。
- 未公开价格。
- 起充较高。
- 无客服渠道。
- 价格信息过期。
- 社区反馈异常。
- 推荐链接。
- 赞助展示。
- 已人工核验。

### 3. 价格数据来源

建议数据来源分层：

- **第一优先级：官方价格页**  
  OpenAI、Anthropic、Google Gemini、DeepSeek 等官方页面。
- **第二优先级：OpenRouter API / 价格页**  
  适合作为跨 provider 的统一参考。
- **第三优先级：LiteLLM / Portkey 等公开模型价格库**  
  适合补充模型列表和上下文数据，但价格需要校验。
- **第四优先级：中转站公开价格页**  
  用于计算最终中转成本，但需要标注来源和更新时间。
- **第五优先级：人工提交 / 社区反馈**  
  可以作为补充，但不能直接作为高可信价格。

## 九、商业化分析

### 1. Google AdSense

AdSense 适合工具站，但前提是页面要有足够原创内容和真实价值。

ModelRate 上线前最好准备：

- 完整首页。
- 至少 10-20 篇原创文章。
- 多个可用工具页面。
- About 页面。
- Contact 页面。
- Privacy Policy。
- Terms / Disclaimer。
- 清晰导航。
- 不误导用户的广告位置。

广告位建议：

- 内容文章中段。
- 工具结果下方。
- 右侧栏。
- 模型详情页中部。
- 中转站详情页底部。

不建议：

- 把广告放在计算按钮附近。
- 把广告做得像下载按钮。
- 首屏堆满广告。
- 只有广告没有实质内容。
- 用赞助站点伪装成自然排名。

### 2. 中转站推荐 / 返佣

这是更贴近业务的变现方式。

可以做：

- 推荐链接跳转。
- 优惠码展示。
- 新用户赠金标记。
- 服务商详情页。
- Sponsor 标记。
- Verified 标记。
- 点击统计。
- 投稿入口。

但需要坚持：

- 推荐关系必须显式标注。
- 价格计算结果不能被赞助影响。
- 排名规则要透明。
- 赞助位和自然结果视觉上区分。
- 不推荐风险过高或数据不透明的站点。

否则网站会很快变成“软广导航站”，长期价值会下降。

### 3. 服务商投稿和认证

后期可以让中转站服务商提交信息：

- 站点名称。
- 域名。
- 支持模型。
- 价格表。
- 倍率表。
- 支付方式。
- 客服链接。
- 优惠码。
- 推荐计划。
- Logo。
- 站点介绍。

人工审核后展示。

认证可以收费，但认证不等于推荐。建议区分：

- `Submitted`
- `Verified`
- `Sponsored`
- `Referral`
- `Community reported`

### 4. 后期增值服务

长期可以考虑：

- 模型价格 API。
- 可嵌入的计算器 widget。
- 团队成本估算工具。
- 企业采购参考报告。
- 价格变化提醒。
- 中转站可用性监控。
- Newsletter。
- 专业版无广告体验。

## 十、MVP 建议

第一阶段不要做太大。建议 MVP 聚焦四件事：

### 1. 一个好用的模型成本计算器

必须做到：

- 输入 token。
- 输出 token。
- 请求次数。
- 模型选择。
- 汇率换算。
- 结果展示清楚。
- 支持官方价和倍率价对比。

这是网站的核心工具入口。

### 2. 一个专业的倍率计算器

必须做到：

- 输入官方输入价和输出价。
- 自动计算模型倍率。
- 自动计算补全倍率。
- 支持 1K / 1M token 切换。
- 支持分组倍率和线路倍率。
- 输出 One-API / New API 可理解的配置结果。

这是网站的专业差异化入口。

### 3. 一个模型价格表

至少收录：

- OpenAI 主流模型。
- Claude 主流模型。
- Gemini 主流模型。
- DeepSeek 主流模型。
- Grok 主流模型。
- 常用开源模型接口价格。
- OpenRouter 常见模型。

字段要完整，尤其是：

- 输入价格。
- 输出价格。
- 上下文长度。
- 数据来源。
- 更新时间。

### 4. 一个中转站目录

初期可以先收录 30-50 家。

不要一开始追求“最多”，要追求：

- 信息准确。
- 字段统一。
- 可筛选。
- 有更新时间。
- 有风险提示。
- 有推荐链接机制。

## 十一、页面结构建议

### 首页

首页不要做空洞宣传页。建议首屏直接放：

- 模型成本计算器入口。
- 倍率计算器入口。
- 热门模型价格表。
- 热门中转站。
- 最近更新数据。
- 一段简短说明：ModelRate 是什么。

首页目标是让用户一进来就能计算。

### 工具页

建议包括：

- 输入区。
- 结果区。
- 公式解释。
- 示例。
- FAQ。
- 数据来源。
- 更新时间。
- 相关文章推荐。

这样既有工具价值，也有 SEO 内容价值。

### 模型页

例如：

```text
/models/claude-sonnet
/models/gpt-5
/models/gemini-pro
```

每个模型页包括：

- 模型简介。
- 输入价格。
- 输出价格。
- 上下文长度。
- 官方来源。
- 中转站价格对比。
- 适合场景。
- 成本计算器。
- FAQ。

### 中转站详情页

例如：

```text
/relay/openrouter
/relay/xxx-api
```

每页包括：

- 站点名称。
- 域名。
- 支持模型。
- 支付方式。
- 起充金额。
- 推荐链接。
- 价格透明度。
- 风险提示。
- 用户注意事项。
- 数据更新时间。

### 指南页

例如：

```text
/guides/what-is-model-multiplier
/guides/how-to-choose-ai-api-relay
/guides/one-api-pricing-guide
```

这些页面负责承接搜索流量和 AdSense。

## 十二、SEO 策略

### 1. 关键词方向

可以围绕以下关键词做页面：

- 模型倍率计算器。
- One-API 倍率计算。
- New API 模型倍率。
- Claude API 价格。
- GPT API 价格。
- Gemini API 价格。
- AI API 成本计算器。
- Token 价格计算器。
- 中转站比价。
- AI 中转站推荐。
- Claude Code 成本。
- Codex API 成本。
- Cursor API 成本。
- OpenRouter 价格对比。
- API 充值能用多久。

### 2. 页面类型

建议形成四类 SEO 页面：

- 工具页。
- 模型价格页。
- 中转站详情页。
- 指南文章页。

这比单纯写博客更稳定，因为每个页面都有明确搜索意图。

### 3. 内容原则

每个页面都应该有：

- 明确更新时间。
- 数据来源。
- 公式解释。
- 示例。
- FAQ。
- 内链到相关工具。
- 风险或免责声明。

不要做薄内容页面。如果页面只有一张表或一个输入框，对搜索和 AdSense 都不够友好。

## 十三、风险分析

### 1. 价格数据变化快

模型价格变化非常频繁。

解决方式：

- 每条数据展示更新时间。
- 标注数据来源。
- 支持用户纠错。
- 核心模型定期人工复核。
- 不承诺绝对实时。

### 2. 中转站质量不可控

中转站可能跑路、改价、限速、换模型、停止服务。

解决方式：

- 明确免责声明。
- 提醒用户小额测试。
- 不建议一次充值太多。
- 标注风险标签。
- 建立社区反馈入口。
- 赞助和推荐必须标注。

### 3. 商业推荐影响可信度

如果用户觉得排名都是广告，网站价值会下降。

解决方式：

- 自然排名和赞助位分离。
- 推荐理由透明。
- 价格计算不受赞助影响。
- 明确 `Sponsored`、`Referral`、`Verified`。
- 保留非商业中立内容。

### 4. AdSense 审核风险

如果网站内容太薄、广告太重、导航不完整，可能不容易通过。

解决方式：

- 先做工具和内容，再申请广告。
- 准备隐私政策、关于页面、联系方式。
- 不做误导点击。
- 不把广告放在核心操作按钮附近。
- 提高原创内容比例。

### 5. 法务和信任风险

中转站本身可能涉及灰色服务，网站需要避免“担保”或“背书”。

解决方式：

- 不承诺服务商稳定性。
- 不代售 API。
- 不处理用户充值。
- 不声称官方合作，除非确实有授权。
- 使用“信息展示”和“价格估算”定位。
- 明确价格仅供参考。

## 十四、执行优先级

### 第一优先级

- 模型成本计算器。
- One-API / New API 倍率计算器。
- 模型价格表。
- 10 篇基础指南。
- 30 家中转站初始目录。

这是最小可上线版本。

### 第二优先级

- 中转站横向比价。
- 预算反推。
- 模型选择器。
- 中转站详情页。
- 推荐链接统计。
- 服务商投稿入口。

这是开始变现和积累数据的版本。

### 第三优先级

- 可用性监控。
- Bench 测试。
- 价格变化提醒。
- Newsletter。
- 模型价格 API。
- 服务商认证。
- 专业版工具。

这是形成壁垒的版本。

## 十五、最终建议

ModelRate 最适合走的路线是：

> 先做可信工具，再做内容流量，最后做推荐变现。

不要一开始做成“中转站广告导航”。更好的切入点是：

- 用倍率计算器解决专业用户的明确痛点。
- 用成本计算器解决普通用户的明确痛点。
- 用模型价格表和中转站目录建立数据资产。
- 用指南文章承接搜索流量。
- 用推荐链接和广告自然变现。
- 用数据透明度和更新时间建立长期信任。

如果只做“中转站推荐”，壁垒很低。如果只做“模型价格计算器”，商业转化弱。如果把二者结合起来，ModelRate 才会有比较清晰的差异化：

> 它既能帮用户算清楚钱，也能帮用户找到更合适的模型和中转站。
